# @deepseek-ai/dsh-host-webserver

English | [中文](README.zh.md)

The web carrier Service Definition (default-exported abstract `WebServer`, `ctx.webServer`): HTTP and WebSocket route registries dispatched over the Fetch standard, the structured index injection table with raw transform taps behind it, and the single fallback seat for everything no route claims. A Service Provider subclasses `WebServer`, owns the listener or platform entry, and forwards every request to `fetch(request)`; [`dsh-host-webserver-node`](../webserver-node/README.md) is the `node:http` provider the shipped Web composition mounts, and a platform provider forwards its fetch entry the same way. `register(route)` adds a named `exact`/`prefix` HTTP route whose handler is `(request: Request) => Response | Promise<Response>`; `registerUpgrade(route)` adds a WebSocket route for an exact pathname with an optional `authorize(request)` that refuses the handshake by returning the HTTP answer and an `open(request, socket)` that drives the accepted socket until it closes. A duplicate path within either table throws because route patterns are a composition-level contract and a collision is a misconfiguration; both methods return a disposer that removes the registration. `registerFallback(handler)` registers the one handler for requests that match no named route. A second registration throws; the SPA dist server [`dsh-host-frontend-static`](../frontend-static/README.md) is the shipped owner, and `fetch` answers 404 while none is registered. Index startup inputs are structured rows: `collectIndexInjections()` gathers a fresh `IndexInjection` table over one `webserver/index-inject` emit per call, and `renderIndex(html)` renders the rows into an index.html body before applying the raw `tapIndex(transform)` transforms in registration order (`applyIndexTaps(html)`, the escape hatch for markup no row expresses); the fallback handler calls `renderIndex` on every index response, and a static deployment ships the same rows over its boot payload, rendering with the exported `renderIndexInjections`. `address` reads the provider's bound `{host, port}` (composition-time facts other plugins adapt to, e.g. the directory-picker chooser and the URL line) and is `undefined` for a provider driven by a platform fetch entry. HTTP match order is fixed: exact over the whole table, then longest prefix, then the fallback handler; `upgradeRoute(pathname)` matches WebSocket routes exactly for the provider's handshake. Registration order carries no request-facing semantics.

The request URL's authority is what the client addressed (its `Host`), so the `/api` trust fence reads it from the request headers; `request.signal` aborts when the client goes away, which is how a streaming response (SSE) learns to stop. `WebServerSocket` is the WHATWG subset every provider can offer (`readyState`, `send`, `close`, `addEventListener` for `message`, `close`, and `error`); a provider that recovers sockets after its own restart calls the route's `open` again with the recovered socket. A route handler's rejection propagates to the provider, which answers it as a per-request failure; the Service Definition never exits the process. The package knows no harness concepts and serves no files: the `/api` route and downlink WebSockets are owned by the connection plugin, plugin bundles and the HMR event stream by the modules/hmr plugins, and dist serving by the fallback owner. This package never prints; the URL line belongs to the shell.

## Model Experience

None, as the package is a Web carrier between the browser and the HTTP/WebSocket routes other plugins register; nothing here reaches a model request.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **No TLS, auth, or origin policy** — the carrier dispatches whatever its provider accepts; deployment hardening belongs to the provider or a reverse proxy in front of it.
- **WebSocket routes are exact-path only** — a socket has one protocol owner, and no shipped consumer needs prefix-matched sockets.
